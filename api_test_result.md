## Summary of Test Cases

### 1. Health Endpoint Returns a Successful Response
* **Endpoint / Method:** `GET /health`
* **Request Payload:** None (GET request)
* **Expected Response:** `{"status": "ok"}`
* **Actual Response:** `{"status": "ok"}`
* **HTTP Status Code:** `200 OK`
* **Pass/Fail Result:** **PASS**

---

### 2. Text Analysis Works with Valid Input
* **Endpoint / Method:** `POST /text/analyze`
* **Request Payload:**
  ```json
  {
    "text": "Hello world from FastAPI"
  }
  ```
* **Expected Response:** Correct word count, character count, and uppercase conversion.
* **Actual Response:**
  ```json
  {
    "word_count": 4,
    "character_count": 24,
    "uppercase_text": "HELLO WORLD FROM FASTAPI"
  }
  ```
* **HTTP Status Code:** `200 OK`
* **Pass/Fail Result:** **PASS**

---

### 3. Text Analysis Handles Empty Input
* **Endpoint / Method:** `POST /text/analyze`
* **Request Payload:**
  ```json
  {
    "text": ""
  }
  ```
* **Expected Response:** Validation error due to `min_length=1` constraint on Pydantic model.
* **Actual Response:**
  ```json
  {
    "detail": [
      {
        "loc": ["body", "text"],
        "msg": "String should have at least 1 characters",
        "type": "string_too_short",
        "input": "",
        "ctx": {"min_length": 1}
      }
    ]
  }
  ```
* **HTTP Status Code:** `422 Unprocessable Entity`
* **Pass/Fail Result:** **PASS**

---

### 6. Invalid Request Payload is Handled Appropriately

* **Request Payload (Too short / below `min_length=20`):**

  ```json
  {

  ```
* **Expected Response:** Pydantic validation rejection for failing minimum length rules.

  ```json

        "input": "Too short.",
        "ctx": {"min_length": 20}
      }
    ]
  }
  ```
* **HTTP Status Code:** `422 Unprocessable Entity`
* **Pass/Fail Result:** **PASS**
