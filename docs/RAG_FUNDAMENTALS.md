# RAG Fundamentals & Core Concepts

This document explains the foundational concepts behind Retrieval-Augmented Generation (RAG) and how they apply to our Document Question-Answering system.

---

### 1. What is Retrieval-Augmented Generation (RAG)?
* **Explanation:** RAG combines an information retrieval system (searching through external documents) with a generative Large Language Model (LLM). Instead of relying solely on what the model memorized during training, RAG fetches relevant facts first and injects them into the prompt so the LLM can generate an accurate, grounded answer.
* **Practical Example:** When asked "What is our company's refund policy?", a RAG system retrieves the specific internal document detailing refund rules and passes it to the LLM to write the final response.

---

### 2. Why is RAG used instead of relying only on an LLM's pretrained knowledge?
* **Explanation:** LLM training data has a cutoff date and lacks access to private, proprietary, or real-time data. RAG eliminates hallucinations, reduces retraining costs, and provides transparent source citations.
* **Practical Example:** An LLM trained in 2024 won't know about a product policy updated yesterday unless retrieved via a RAG system.

---

### 3. What are document ingestion and indexing?
* **Explanation:** Ingestion is the process of loading raw documents from storage, and indexing involves converting their text into searchable data structures (like vector embeddings) for fast similarity matching.
* **Practical Example:** Reading `documents.json`, splitting text, generating embeddings, and storing them in memory or a vector database.

---

### 4. What is document chunking?
* **Explanation:** Breaking large documents into smaller, manageable segments (e.g., 300-500 characters) so that retrieval can pinpoint exact paragraphs rather than returning an entire lengthy document.
* **Practical Example:** Splitting a 10-page manual into individual paragraph chunks with unique chunk IDs.

---

### 5. What is an embedding?
* **Explanation:** A dense vector (array of floating-point numbers) generated by an AI model that captures the semantic meaning of a piece of text in a multi-dimensional space.
* **Practical Example:** Converting the sentence "How to secure an API" into a vector like `[0.15, -0.42, 0.88, ...]`.

---

### 6. What is a retriever?
* **Explanation:** The component responsible for taking a user query, generating its embedding, comparing it against indexed chunk embeddings using similarity metrics (like cosine similarity), and returning the top-K most relevant chunks.
* **Practical Example:** Searching the vector index for the top 3 chunks closest to the user's question vector.

---

### 7. What is retrieval relevance?
* **Explanation:** A measure of how closely the retrieved text chunks match the actual informational intent of the user's query. High relevance means the retrieved text contains the exact facts needed to answer the question.
* **Practical Example:** Retrieving a chunk about "API rate limiting" when the user asks about securing API traffic.

---

### 8. What is a context window?
* **Explanation:** The maximum amount of text (measured in tokens) that an LLM can accept in a single input prompt for processing.
* **Practical Example:** Passing 3 retrieved chunks totaling 1,000 tokens into Gemini's input window which supports up to 1 million+ tokens.

---

### 9. What is prompt grounding?
* **Explanation:** Restricting the LLM's behavior by explicitly instructing it to rely *only* on the provided retrieved context rather than its internal parametric memory.
* **Practical Example:** Prompting: "Answer the question using *only* the context provided below. If the answer is not present, state that you do not know."

---

### 10. What are source citations in a RAG system?
* **Explanation:** Metadata references (document IDs, titles, and chunk IDs) returned alongside the answer to prove which documents supplied the facts used in the response.
* **Practical Example:** Showing `` under the generated answer.

---

### 11. What is the difference between semantic search and RAG?
* **Explanation:** Semantic search only *retrieves* relevant documents based on meaning. RAG takes it a step further by passing those retrieved documents to an LLM to *synthesize* a direct, natural language answer.
* **Practical Example:** Semantic search gives you a list of 3 matching PDF links; RAG reads those PDFs and writes a direct answer paragraph summarizing them with citations.

---

### 12. What is the difference between RAG and fine-tuning?
* **Explanation:** Fine-tuning alters the internal weights of an LLM to change its style, tone, or domain expertise permanently. RAG externalizes knowledge, keeping the base model unchanged while injecting dynamic facts into the prompt at runtime.
* **Practical Example:** Fine-tuning teaches an LLM medical terminology; RAG looks up today's live patient chart in a database.

---

### 13. What happens when retrieval returns irrelevant documents?
* **Explanation:** The LLM receives unhelpful context, leading to poor answers, hallucinations, or unnecessary refusals even if the correct answer exists elsewhere in the database.
* **Practical Example:** Asking about billing policies and retrieving marketing brochures instead.

---

### 14. Why can a RAG system still generate an incorrect answer?
* **Explanation:** Due to LLM hallucinations, misinterpretation of context, or because the retrieved chunks contained ambiguous/conflicting information.
* **Practical Example:** The LLM misreads a nuanced clause in the retrieved context and states an incorrect rule.

---

### 15. What should a RAG system do when the available documents do not answer the question?
* **Explanation:** It should gracefully abstain (say "I cannot answer this based on the provided documents") rather than hallucinating an answer.
* **Practical Example:** Responding with "I do not have enough information in the provided documents to answer your question."
